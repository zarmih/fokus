# I18N G13 — RU/EN completeness

Shell, Today, Program (session), Settings, and Result speak both Russian and English from one dictionary. Catalog files stay as they are.

## Architecture

```
src/core/i18n.ts            t(), setLocale, parity helpers, UI/core copy
src/core/i18n-exercises.ts  name + instruction overlay per exercise id
src/core/labels.ts          domain / skill / league / exerciseName()
```

`t(key, vars?)` interpolates `{name}` slots. Missing keys return the key. Default locale is `ru`. `initI18n` reads `profile.language || profile.locale` and sets `document.documentElement.lang`.

Exercise modules keep Russian `manifest.name` / `manifest.instruction`. Screens never read those fields raw: they call `exerciseName(id)` / `exerciseInstruction(id)`, which resolve `ex.{id}.*` without touching `registry.ts`.

## Surfaces

| Surface | Files | What is translated |
|---|---|---|
| Shell | `ui/shell.ts` | Tab labels |
| Today | `ui/screens/today.ts` | Greeting, plan card, quests, coach, lifestyle prompt |
| Program | `ui/screens/session.ts` | Block chrome, pause/fatigue, instruction card |
| Settings | `ui/screens/settings.ts` | Every control, confirm, alert, disclaimer |
| Result | `ui/screens/result.ts` | Hero, deltas, progression, share, next step |

Copy that those screens *display* also lives in the dictionary even when it is produced in core: coach sparks, daily quests, insights, plan reasons, Fokus Index deltas, achievement names, share card, local reminder body.

## Locale storage

- `profile.language` is what Settings already wrote.
- `profile.locale` is the same `'ru' \| 'en'` value (widened from a `'ru'` literal).
- Changing language writes both, then reloads.

## Parity rules

- Every key has non-empty `ru` and `en`.
- English must not contain Cyrillic except `settings.lang` and `settings.lang_ru` (the language switcher itself).
- Every registry id has `ex.{id}.name` and `ex.{id}.instruction`.
- Tests in `tests/i18n.test.ts` enforce this. `tests/setup.ts` resets locale to `ru` so existing Russian assertions stay stable.

Regenerate the exercise overlay after adding a catalog game:

```bash
python3 scripts/gen-i18n-exercises.py
```

Add the English pair in that script first. Do not edit `registry.ts` for labels.

## Out of scope

- Onboarding, trainers catalog body, analytics, duel, weekly review, in-exercise HUD.
- Phase 2 Program tab (not on `main`). Session chrome is the program surface here.
- `registry.ts` and exercise modules — no churn unless a new game needs overlay keys.
- Boot splash in `index.html` (renders before `initI18n`).
