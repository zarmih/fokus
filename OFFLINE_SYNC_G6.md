# Offline Sync G6 — локальное хранилище Fokus

Fokus остаётся PWA без сервера пользовательских данных. «Синхронизация» — это файл между устройствами плюс хранилище, которое не теряет прогресс при обновлении схемы, битой записи или неудачном импорте.

Не облако, не аккаунт, не конфликт с чужим профилем на сервере.

## Зачем

Было: один ключ `fokus.v1` в `localStorage`, сырой JSON, импорт = полная замена, порча файла → пустой профиль, история обрезалась на 30 записях.

Нужно: версионированный конверт, цепочка миграций, объединение двух офлайн-копий, контрольная сумма, снимок «как было» до импорта.

## Модель

Источник правды — локальный `AppState`. UI по-прежнему ходит только в `storage.*`. Ядро синка — чистые функции в `src/core/offline-sync.ts` (без DOM и без `localStorage`).

```
Экран «Настройки»
        │
        ▼
   Storage (бакенд + снимок + bak)
        │
        ▼
   offline-sync: migrate / envelope / merge / preview
```

Ключи:

| Ключ | Роль |
| --- | --- |
| `fokus.v1` | живое состояние |
| `fokus.v1.bak` | последний успешно разобранный live перед новой записью |
| `fokus.v1.snap` | снимок перед импортом (для «вернуть как было») |

Бакенд тот же: `getItem` / `setItem` / `removeItem`. IndexedDB не вводился — это отдельный объём и ломает существующие тесты/обёртки.

## Схема

`CURRENT_SCHEMA_VERSION = 4`. Каноническая версия живёт в `meta.schemaVersion`, зеркало — `profile.schemaVersion` (как в v1–v3).

| С → | Что делает миграция |
| --- | --- |
| 1 → 2 | `onboarded` из `calibrated`, пустые `history` / `skills` |
| 2 → 3 | `skills.sources`, `mastery` / `stability` / `consecutivePlateau` |
| 3 → 4 | `meta` (deviceId, rev, updatedAt), дедуп коллекций по id/дате |
| 4 | heal: обязательные поля профиля, не перетирать существующий `deviceId` |

Нет версии или нет `schemaVersion` → считается v1. Версия **новее** текущей — отказ, live не трогаем.

`rev` монотонно растёт на каждой успешной записи. `deviceId` выдаётся устройству при первой записи и не меняется при импорте.

## Конверт экспорта

```json
{
  "kind": "fokus-backup",
  "format": 1,
  "exportedAt": "ISO-8601",
  "checksum": "fnv1a-32-hex",
  "payload": { "...AppState" }
}
```

`checksum` — FNV-1a 32-bit от `JSON.stringify(payload)`. Это целостность, не криптография. Красивая печать всего файла допустима: считается уже разобранный объект payload.

Старый дамп `{ "profile": ... }` без конверта принимается как format 0 (`legacy_raw`) и прогоняется через миграции.

Отказ:

- не JSON
- нет `profile` и это не `fokus-backup`
- `format` > 1
- схема payload > 4
- несовпавшая сумма format 1

## Объединение

Импорт по умолчанию — **merge**. Replace — явный выбор в UI.

| Коллекция | Ключ | Правило |
| --- | --- | --- |
| sessions | `id` | объединение; при споре — позже `finishedAt` |
| daySummaries | `date` | богаче `totalScore`; если хотя бы одна копия сыграна — день не skipped |
| history | `date` | выше `score` |
| exerciseStates | `exerciseId` | позже `lastPlayedAt`; `attempts` / `mastery` — max |
| skills | `skill` | позже `lastUpdated`; `sources` — объединение |
| domains | `domain` | позже `updatedAt` |
| profile | — | скаляры по более новому `meta.updatedAt`; XP — max; achievements — объединение; `onboarded` / `calibrated` — ИЛИ; `createdAt` — более ранний |

Replace подставляет payload, но **оставляет local `deviceId`**. Перед обоими режимами live копируется в `fokus.v1.snap`.

История больше не режется на 30 записей.

## Долговечность записи

1. Если текущий live парсится — он уходит в `.bak`.
2. Пишется новый live.
3. Если `setItem` бросил (квота) — live остаётся прежним, `.bak` откатывается.
4. При чтении битого live — подъём из `.bak` и повторная миграция.
5. Битый JSON без bak → дефолтный профиль (как раньше), не тихий null в середине сессии.

Конструктор мигрирует на месте и пишет v4, только если версия выросла или не было `meta`.

## UI

Экран «Настройки» → «Данные»:

- строка здоровья: схема, ревизия, короткий deviceId, размер
- Экспорт — файл `fokus-backup-YYYY-MM-DD.json`
- Импорт — превью (имя, XP, новые сессии/дни), затем **Объединить** или **Заменить**
- «Вернуть резервную копию», если есть snap
- Сброс по-прежнему чистит live + bak + snap

## Ограничения

- Нет серверного синка и нет multi-master CRDT. Два файла = merge/replace вручную.
- FNV-1a не защищает от злонамеренной подмены, только от обрыва/редактирования вслепую.
- `localStorage` остаётся потолком размера. При квоте новая запись не применяется, старая не уничтожается.
- Дедуп дней и истории идёт по точному `date` (в сессии это полный ISO), не по календарному дню.
- Реестр упражнений и экраны сессии/результата не менялись.
